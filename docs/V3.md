## 1. 这次改了什么

V2 是暗色背景 + 发光卡片 + 三列规则网格 + 装饰编号的首页。V3 把它重构为
**Light Futurism × Editorial Photography × Liquid Glass × Spatial Computing**：

| 维度 | V2 | V3 |
|---|---|---|
| 基底 | 曜石黑 (#05070A) | 珍珠白 / 雾白 (#F4F6F8)，**地球页与灯箱保留深色** |
| 首页结构 | 三列七窗口网格 + 统计条 + 编号 | 三层：中央品牌 → 左右双核心窗口 → 次级入口 |
| 品牌写法 | `TangyuanVision`（拼音） | **汤圆Vision** + 中文释义 **汤圆视界** |
| 三维 | 仅首页 HubBackdrop 装饰性 WebGL | **真实可交互地球**（昼夜、灯光、云层、大气、射线拾取） |
| 访客数据 | 无 | Supabase 共享点赞与投票（未配置时明确报不可用） |
| 启动动画 | 1650 ms | 1200 ms，可跳过，有硬性兜底 |

### 移除的内容（按需求要求）
- 统计条（窗口数、条目数、版本号、"online" 状态）
- 每张卡片上的 `01/02/03` 装饰编号
- 七窗口等宽网格

## 2. 「汤圆视界」与品牌写法

**这是本次新增的。** 改前全仓库搜索 `汤圆视界` **零命中**——V2 只有 `TangyuanVision`。

现在的品牌是三个**互不从属**的字段，因为它们排版方式不同，不能互相拼装
（见 `src/content/types.ts` 的 `BrandIdentity`）：

| 字段 | 值 | 用途 |
|---|---|---|
| `brandFull` | 汤圆Vision | 完整锁定组合 |
| `nickname` | 汤圆 | 仅需中文一半时 |
| `brandLatin` | Vision | 拉丁部分，用展示字体 |
| `brandGloss` | 汤圆视界 | 中文释义，**必填** |

主标题排版刻意制造对比：中文部分 `font-weight: 600`、拉丁部分 `300`，
两者之间**不留空格**（留空格就变成两个词，不是一个名字）。

`TangyuanVision` 仍然存在于**仓库路径**中（GitHub 仓库名就叫这个，
所以 `/TangyuanVision/` 的 base 路径是正确的，必须保留）。
它不再作为**显示用的品牌名**出现在任何地方，只剩三处注释专门说明"不要使用"。

## 3. 三维地球

### 3.1 纹理来源（已核验许可）

`tools/build-earth-textures.cjs` 拉取并处理纹理，同时把**上游文件、原始尺寸、
许可、体积**写进 `public/assets/earth/textures.json`。全部为**公有领域**：

| 用途 | 来源 | 原始尺寸 | 许可 |
|---|---|---|---|
| 昼面 | NASA/Goddard — "Whole world - land and oceans" | 12000×6000 | Public domain |
| 夜间灯光 | DMSP 1994–1995（NASA GSFC / NOAA NGDC） | 4800×2400 | Public domain |
| 云层 | three.js 示例素材 | 1024×512 | MIT |
| 海陆遮罩 | 由昼面纹理派生 | — | 派生自公有领域 |

**必须说明的两点：**
1. **夜间灯光是 1994–1995 年的数据**，距今约三十年。它是真实观测的城市灯光分布，
   但**不代表当下**。UI 与文档都没有把它说成实时数据。
2. **地表是静态贴图，不是实时卫星画面。** 昼夜分界由本地计算，但贴图本身固定。

### 3.2 昼夜与实际太阳位置

`src/features/earth/solar.ts` 用标准低精度太阳位置算法计算**太阳直射点**
（含均差修正、黄赤交角、时差方程）。误差小于 1°。

**它不是**精密星历：省略了章动、光行差、大气折射。UI 里明确写了
「由本地按当前 UTC 时间与太阳赤纬计算」，没有声称是天文模拟。

**实测验证**：截图时刻（UTC 19:15）太阳直射点为 6.1°E，
渲染结果显示**西非处于日间、欧洲亮起城市灯光、昼夜分界落在两者之间**——
与直射点位置一致。

### 3.3 旋转约定（推导得出，不是猜的）

`THREE.SphereGeometry` 的 UV 映射加上等距柱状投影的经度对应关系，推导出：

```
rotation.y = -90° - longitude
```

上一版写的是 `rotation.y = +subLon`，**会导致开场显示夜半球**，而页面上的
太阳直射点读数却说另一侧是白天——这是自相矛盾的。现已修正为面向直射经度，
所以访客先看到受光面。

### 3.4 国界识别

`src/features/earth/geo-index.ts`：

1. 指针坐标 → NDC → 射线（three.js Raycaster）
2. 射线与球面求交 → 交点 → 经纬度
3. 经纬度 → **1° 网格空间索引** → 国家

**为什么用空间索引**：177 个国家共约 3 万个多边形顶点。逐个国家做点在多边形内
测试要几毫秒——一次可以，60fps 下指针一动就是灾难。索引把候选缩小到 1–4 个。

`±180°` 接缝单独处理（俄罗斯、斐济、新西兰的包围盒会被拆成两个），
处理错会**静默丢失整个国家**。

国界数据：Natural Earth 1:110m（公有领域），177 国，105 KB。
该精度下小岛屿与部分边界会简化或缺失——这一点写进了页面。

### 3.5 中文国名

内置 177 国中的约 120 个中文名（`regions.ts`），**刻意是部分映射**。
映射表外的国家回退到数据源里的**英文名**，而不是机器翻译——
一个错误的中文名比一个正确的英文名更糟。列表排序把有中文名的排前面。

### 3.6 地区面板的三种状态

必须区分，不能模糊：

| 状态 | 面板行为 |
|---|---|
| `visited` | 显示真实记录：日期、正文、照片、坐标 |
| `planned` | 说明在计划中，**明确说明计划不等于经历** |
| `unrecorded` | 直说"我还没有去过这里"，**不编造任何日期、路线、照片** |

`src/content/data/travels.json` **当前为空数组**，这是刻意的。
没有提供任何真实旅行记录时，页面为每个国家显示「尚未记录」。

### 3.7 WebGL 降级

WebGL 完全不可用时显示**经过设计的静态地球预览**（不是空白错误框），
并保留地区列表浏览与投票能力。已在真实浏览器中验证该路径。

## 4. 一个真实的兼容性缺陷（已修复）

**现象**：地球页在无头 Edge 154 中显示回退面板，但能力探针证明
`webgl2` **可用**（NVIDIA GPU、可绘制、readPixels 正确）。

**排查过程**（每一步都有实测证据，不是猜测）：

1. 显式创建 context 交给 three.js → 拿到的 context `isContextLost() === true`、
   `drawingBufferWidth === 0`
2. 对照探针：同样的容器 CSS、同样的画布样式、同样的属性、同样的 1400×1000 尺寸，
   **在组件外同步执行时成功**
3. 打开浏览器控制台日志，拿到关键行：
   ```
   THREE.WebGLRenderer: Context Lost.
   [earth] renderer construction failed: Cannot read properties of null (reading 'precision')
   ```

**根因**：three.js 释放了它无法使用的 context 后，**该 `<canvas>` 永久失效**。
按 HTML 规范，画布一旦确定了 context 模式就不能更换，丢失的 context 不会在该元素上
被替换，因此之后每次 `getContext()` 都返回 `null`。
**在同一个 `<canvas>` 上重试是永远不会成功的**——这正是四次尝试产生四条相同错误的原因。

**修复**：每次重试**换一个全新的 `<canvas>` 元素**。
这同时也是生产环境中真正的 context 丢失（驱动重置、切换显卡、笔记本拔掉扩展坞）
唯一正确的恢复方式。

**修复后实测**：attempt 1 丢失 context → attempt 2 用新画布成功 →
`data-ready="true"`、无回退面板、DOM 中恰好一个 canvas。

## 5. 视觉验收与一个假警报

### 5.1 已确认正常的
首页浅色重构真实完成（不是只改背景色）：截面几何、字体层级、留白、图片比例都改了。
品牌居中、汤圆视界可见、拼音写法不在 DOM 中、摄影在左、地球在右、
核心窗口明显大于次级入口——全部由 `tools/verify-v3.cjs` 断言。

### 5.2 截图看起来页面是半透明的——排查结论：**测试环境的假警报**

截图显示摄影页文字呈 ~40% 透明度。这可能是两种完全不同的情况：
（a）截图拍在过渡动画中途；（b）`.reveal.is-armed` 把内容设成 `opacity: 0`
等 IntersectionObserver，若观察器不触发则内容**永久不可见**。

（b）是严重缺陷，不能当成截图问题一笔带过。所以写了
`tools/audit-reveal.cjs`：在受测文档里注入 `transition: none !important`，
让所有待决过渡立即结算，**测的是稳定态而不是运动中的快照**，
并把三种情况分开统计：

- 在视口内且仍为 0 → 缺陷
- 在视口外 → 这是滚动显现**按设计工作**

**结果：0 个元素卡住。** 所有 `.is-revealed` 元素在结算后都正常显示。

**剩下的路由外壳透明度**（0.92 左右）也查清了：`route-shell` 用 Motion 从 0.08
动到 1，Motion 靠 `requestAnimationFrame` 推进。实测无头截图的
**rAF 帧数 = 4~6 帧 / 6000ms**（约每秒 1 帧，真实显示器约 60 帧）。
420ms 的动画在总共 5 帧里**不可能走完**，所以读到 0.92。

同一测量放到**顶层文档**（非 iframe）时，4 条路由中 3 条到达 0.9999。
结论：**是本环境无法产生动画帧，不是产品问题**。

> 诚实说明：`tools/audit-reveal.cjs` 保留在仓库中，它的判据是
> 「在视口内且仍为 0」，这个判据本身是有效的。

## 8. 已知限制与取舍

- **在线投票无法做到"一人一票"。** 没有登录就没有身份。`visitor_hash` 是本地随机
  UUID 加盐哈希，清除站点数据/无痕/换浏览器就是新访客。**真正不可绕过的只有数据库
  的 `UNIQUE` 约束**，其余都是尽力而为的减速带。文档里也是这么写的。
- **CMS 上传不清理孤儿文件。** 替换图片后旧文件会留在仓库里。
- **无头环境与真实浏览器的行为差异**已在第 5、7 节说明，不要据无头结果推断真机表现。
- **`水印黑.png` 不存在。** 本机只有 `C:\Users\pc\Pictures\水印白.jpg`
  （JPEG，无 alpha）。`logo-dark.png` 是**由白色版派生的着色版本**，
  不是缺失的原文件。这一点在 `brand.json`、关于页与文档中都已标注。
