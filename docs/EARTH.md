# 地球 Online 进度 — 内容与数据

本文说明「地球」专题的内容结构、如何录入真实旅行记录，以及共享投票数据层的边界。

---

## 1. 两层数据，必须分清

| 层 | 存放位置 | 谁写 | 内容 |
|---|---|---|---|
| **内容** | `src/content/data/travels.json`（Git） | 你，通过 CMS 或直接编辑 | 你去过哪里、什么时候、故事、照片 |
| **访客互动** | Supabase（托管数据库） | 访客 | 点赞数、"我也想去" 票数 |

**不要把访客互动数据写进 Git 文件。** 静态文件无法承载共享计数——
每个访客拿到的都是一份只读副本，写进去只会让所有人看到同一个数字。

**也不要假设 CMS 能提供共享计数后端。** Decap CMS 只是把你写的内容提交到 Git 仓库，
它没有任何实时写入能力。

---

## 2. 地理事实 vs 个人经历

系统里有两件必须分开的事：

- **地区是地理事实。** 国界、ISO 代码、位置来自 Natural Earth（公有领域），
  与你是谁无关，177 个国家与地区全部可识别。
- **到访是你的个人记录。** 它来自 `travels.json`，**没填就是没填**。

分开的原因很直接：混在一起，一个从未去过的地方会看起来像去过。

---

## 3. 当前状态

`src/content/data/travels.json` **的 `items` 是空数组**。这是刻意的：

- 地球能识别 177 个国家与地区
- 但**没有任何一条真实旅行记录**
- 所以每个国家都显示「尚未记录」，并说明这是准确的状态而非疏漏

页面头部的统计（已到访 / 计划中 / 可识别）**由内容实时计算**，
没有硬编码。你现在看到的会是 `0 / 0 / 174`。

> 174 而不是 177：数据集里有 3 个几何要素没有可用的数字 ID，构建索引时被跳过。
> 这是数据源的问题，不是遗漏。

## 4. 如何录入真实旅行记录

### 方式一：CMS（推荐）

```bash
# 终端 A
pnpm dev
# 终端 B（本地写入后端）
pnpm cms
```

打开 http://127.0.0.1:5183/admin/ → 「地球与旅行」集合 → 新建。

### 方式二：直接编辑 JSON

编辑 `src/content/data/travels.json`：

```json
{
  "items": [
    {
      "regionId": "156",
      "status": "visited",
      "title": "环青海湖",
      "visitedAt": "2026-07-14",
      "story": "第一段……\n\n第二段……",
      "photoIds": ["my-photo-01", "my-photo-02"],
      "latitude": 36.62,
      "longitude": 100.11,
      "published": true
    }
  ]
}
```

### 字段说明

| 字段 | 必填 | 说明 |
|---|---|---|
| `regionId` | ✅ | ISO 3166-1 **数字**代码，字符串。中国 `"156"`、日本 `"392"`、美国 `"840"` |
| `status` | ✅ | `visited` \| `planned` \| `unrecorded` |
| `label` | | 覆盖内置中文名。只在默认名不对时才填 |
| `title` | | 例如一次旅行的名字 |
| `visitedAt` | | `YYYY-MM-DD`。**只有真的去过才填** |
| `story` | | 正文，空行分段 |
| `photoIds` | | 引用 `photography.json` 里的作品 `id` |
| `latitude` / `longitude` | | **只有记录了具体地点时才填** |
| `published` | | 是否公开显示 |

### 三种状态在页面上的行为

- **`visited`** → 显示日期、正文、关联照片、坐标（填了才显示）。
  正文或照片为空时显示「这次旅行还没有写下正文」，**不补造内容**。
- **`planned`** → 说明在计划中，并明确写出「计划不等于经历」。
- **`unrecorded`** → 直说「我还没有去过这里，因此这里没有任何旅行记录」。
  **不编造日期、路线、照片或来源。**

## 5. "我也想去" 投票

### 需要先配置数据库

投票走 Supabase。完整配置步骤见 [`supabase/README.md`](../supabase/README.md)。

需要填两个环境变量（见 `.env.example`）：

```
VITE_SUPABASE_URL=https://<project-ref>.supabase.co
VITE_SUPABASE_ANON_KEY=<anon/public key>
```

这两个值是**公开的**——它们会打进前端产物，任何人都能看到。
安全性来自 **Row Level Security**，不是来自隐藏这个 key。
**绝对不要**把 `service_role` key 放进前端、仓库或任何 `VITE_*` 变量。

### 未配置时的行为

**不会显示任何票数。** 不显示 `0`，不显示随机数，不显示假成功。
面板会显示明确的「共享投票暂不可用」并解释原因——
显示一个编造的 `0` 也是编造数据。

### 安全边界（如实说明）

**真正不可绕过的只有数据库约束**：
`UNIQUE(region_id, visitor_hash)` 让同一令牌的第二行**不可能**存在，
Postgres 的 `23505` 一律被如实报成「已投过」。

**其余都是尽力而为的减速带，文档里也是这么写的：**

- 没有登录就没有身份。`visitor_hash` 是本地随机 UUID 加盐 SHA-256。
  清除站点数据、用无痕窗口、换个浏览器，就是新访客。
  **"一人一票"做不到，本项目也不声称能做到。**
- select/delete 策略靠 `x-visitor-hash` 请求头收窄，那是一串可以随手伪造的字符串。
  它的真实收益是**令牌无法通过 REST 接口被枚举**（必须先知道某个令牌才能读/删它的行），
  挡的是"顺手遍历"而不是"蓄意冒充"。
- 300 秒 / 20 次的限流是**每令牌的配额，不是安全控制**——换令牌即重置。
  它放在触发器里，是因为 RLS 根本无法表达"过去一小时写了几次"。
- 真正的兜底是：anon 连 UPDATE 权限都没有、原始 `visitor_hash` 行永不暴露
  （计数只经 `security definer` 函数返回 `{id, count}`）、
  以及**永不渲染编造的数字**。

### 写入成功但回读失败时

计数会变成 `null`（显示为 `—`），**而不是 `上一次 + 1`**。
因为"我写进去了但读不到"和"现在是 3 票"是两件事，后者是猜测。

## 6. 中文国名从哪来

`src/features/earth/regions.ts` 里有约 120 个中文名，**刻意是部分映射**。

映射表外的国家回退到数据源里的英文名——**没有经过机器翻译**，
因为一个错误的中文名比一个正确的英文名更糟。

想补某个国家的名字，在 `REGION_LABELS` 里加一行：

```ts
'392': '日本',   // ISO 数字代码 -> 中文名
```

或者在某条旅行记录里用 `label` 字段单独覆盖。

## 7. 数据来源与许可

| 用途 | 来源 | 许可 |
|---|---|---|
| 昼面纹理 | NASA/Goddard — "Whole world - land and oceans" | 公有领域 |
| 夜间灯光 | DMSP 1994–1995（NASA GSFC / NOAA NGDC） | 公有领域 |
| 云层 | three.js 示例素材 | MIT |
| 国界 | Natural Earth 1:110m | 公有领域 |

完整的上游文件、原始尺寸、许可与体积记录在
`public/assets/earth/textures.json`（由 `tools/build-earth-textures.cjs` 生成）。

**两点必须知道：**

1. **夜间灯光是 1994–1995 年的数据**，是真实观测，但距今约三十年，
   不代表当下的灯光分布。页面与文档都标注了这一点。
2. **地表是静态贴图，不是实时卫星画面。** 昼夜分界是本地按真实太阳位置算的，
   但贴图本身是固定图像。
