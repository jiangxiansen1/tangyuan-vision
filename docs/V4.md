## 1. 全局颜色变量错误（已修复，有实测证据）

### 用户报告的现象成立，但根因与描述不同

报告说「画布与文字可能完全相同」。实测确认**症状真实存在**，但根因是**变量角色用错**，而
不是简单的取值问题：

```css
/* tokens.css —— 修复前 */
--c-mist: var(--c-ink);          /* 叠加色，本意是「在任意底色上叠一层淡覆盖」 */
--color-canvas: var(--c-mist);   /* ← 把叠加色当成了涂色 */
--color-text: var(--c-ink);
```

`--c-mist` 被引用 **72 次，其中 60 次**是 `color-mix(in srgb, var(--c-mist) N%, transparent)`
形式——它的职责是**半透明叠加层**（hover 填充、细线、骨架屏）。把这样一令牌当作不透明涂色
使用，画布就会解析为 `#161b22`，与文字同色。

### 浏览器实测（修复前）

```
--color-canvas : #161b22
--color-text   : #161b22
canvas==text   : true
```

后果实测：摄影页 **36 个元素**对比度为 **1:1**（前景与背景同色，即不可见）；
`<h1>摄影` 计算样式 `fg=rgb(22,27,34) bg=rgb(22,27,34)`。**9 条路由全部受影响。**

### 修复方式

```css
/* tokens.css —— 修复后 */
--c-mist: var(--c-ink);            /* 保持叠加语义，不再用作涂色 */
--color-canvas: var(--c-mist-soft); /* 真正的浅色表面 #f4f6f8 */
```

**没有使用任何 `!important` 掩盖问题**，也没有只改根背景：`--c-mist` 的 60 处
`color-mix` 用法全部保持不变——它们本来就是对的。

### 连带发现并修复的 4 个真实缺陷

画布修正后，把本来被「全局都错」掩盖的问题暴露出来：

| # | 缺陷 | 实测症状 | 修复 |
|---|---|---|---|
| 1 | `secret` 页只声明令牌、不消费它 | `base.css` 在 `<body>` 上解析 `color`，令牌虽在 `.secret` 重新指向却无人读取 → 1.08:1 | `.secret` 自身 `color: var(--color-text)` 重启继承链 |
| 2 | 强调色作小号文字不达标 | cryo 3.89:1、amber 3.39:1、aurora 3.98:1 | 加深至 5.42 / 5.19 / 5.82:1 |
| 3 | 地球页曾整体声明 `data-ground="dark"` | 地区列表与致谢区继承近黑底，文字却仍是浅色版令牌 | 改为浅色地面，深色只限定在球体井内 |
| 4 | 地球页标题在地球井内用 `var(--color-text)` | 深墨字压在深色渐变上 | 改白色并加文字投影 |

**最终实测：9/9 路由无低对比文字。**

> 测量局限（已写进脚本）：多色标 CSS 渐变的对比度以首色标近似，且部分渐变的
> 计算值无法可靠解析。因此单条告警应理解为「去看一眼」，不等于确诊缺陷。

## 2. 首页布局：三栏，品牌居中

### 结构

```
[ 摄影主窗口 ]   [ 汤圆Vision / 汤圆视界 /     ]   [ 地球 Online 进度 ]
                 [ A WORLD BEYOND THE FRAME    ]
        ↓ 次级入口：AI 与编程 Lab、个人项目 ↓
        ↓ 轻量链接：关于我、随笔、联系、隐藏空间 ↓
```

**品牌真的在两个窗口之间**，不是上方标题区——这一点由**结构**保证：品牌是同一
grid 的中间轨道，与两个窗口是**兄弟关系**，因此任何宽度下都不可能漂到上方。

```css
grid-template-columns: minmax(0, 1fr) auto minmax(0, 1fr);
```

中间轨道是**内容驱动（auto）**而非固定宽度。第一版写成固定 `clamp(240px,30vw,460px)`，
与锁字自身的流体字号形成**两个互相不知道的 clamp**，实测结果是文字压到左右两个窗口上。

### 实测

| 项 | 结果 |
|---|---|
| 品牌位于两窗口之间 | PASS（按 class 属性比较 DOM 顺序） |
| 摄影在左、地球在右 | PASS |
| 无横向溢出 | PASS |

### 移动端

`≤1023px`：品牌跨两列置顶，两个窗口并列；`≤767px`：单列，品牌→窗口→次级入口。

## 3. 液态玻璃材质（真实生效，有实测）

### 之前的问题

`CoreWindow` **从未导入 `GlassSurface`**。它是一个带深色遮罩、1px 边框和阴影的普通
`<button>`，而且预览图以**完全不透明**铺满整个表面——**不透明子元素会让
`backdrop-filter` 无内容可采样**，材质在物理上不可能出现，无论 CSS 怎么写。

### 三处必要改动（缺一不可）

1. 表面改用 `GlassSurface`（`tier="refract"`），六层由设计系统提供
2. 预览图**半透明**（`opacity: 0.62`），遮罩只覆盖**下三分之一**（文字所在处）
3. 环境背景与玻璃面板处于同一层叠上下文，让模糊有结构可采样

### 浏览器实测

```
FILTER  365x456  .glass glass--refract cwin__surface
    backdrop-filter : blur(8px) saturate(1.85) url("#tv-liquid-refract")
    url() refraction: true    pane opaque bg: false
    covers: .glass__specular opacity=0
            .glass__dispersion opacity=0.34
            .glass__chroma opacity=0.5
            .cwin__preview opacity=0.62

4/4 panes carry a real backdrop-filter
No pane is blocked by opaque content.
```

**这是真实 SVG 折射**（`url("#tv-liquid-refract")`），不是仅仅存在 `backdrop-filter`
声明——检查脚本专门验证「是否有不透明子元素挡住采样」。

## 4. 路由转场：现在真的有退出阶段

### 之前为什么不工作

每条路由**各自**包一层 `<SceneTransition>`。这读起来合理但不可能工作：每条路由拥有
自己的状态与 `motion.div`，路由切换时**旧组件立即被卸载**，没有东西留下来执行退出动画。
只增加时长无法修复——**必须改变组件生命周期**。

### 现在的实现

动画容器移到**路由切换之上**（`RouteTransition` 包住整个 `<Routes>`），由它统一管理
退出与进入：

| 入口 | 类型 | 处理 |
|---|---|---|
| 摄影、地球 | `shared` | 目的地主视觉从 0.955 缩放生长 + 淡入，随后其余内容延迟进入 |
| 其余页面 | `scene` | 短淡入上移 |
| 隐藏空间 | `immersive` | 更快的整体推进 |

退出页以 `position: absolute` 脱离文档流（否则两页同时存在于普通流会让文档高度翻倍
然后跳变），并设 `pointer-events: none`（否则不可见的旧页仍会吞掉点击）。

### 实测（在页面内驱动真实导航并逐帧采样）

```
max route shells DURING the navigation : 2
two shells coexisted                   : true
an exiting shell was flagged           : true
exit opacity range                     : 0 .. 0.17     ← 由 0 升到 0.17 淡出
PASS
```

**两个 shell 同时存在、且旧页真的在淡出**，这就是「有退出阶段」与「只是切换」的分界。

### 诚实说明：这不是 `layoutId` 几何插值

摄影与地球的连续性用的是**缩放+淡入**，不是 Motion 的 `layoutId` 共享元素插值。
原因有二，都不是偏好问题：

1. 目的地是 **lazy 路由，位于 Suspense 之后**——交接开始时第二个几何体还不存在，
   `layoutId` 无法朝一个尚未挂载的盒子插值。
2. 地球目的地内含**活动的 WebGL canvas**，在过渡中对整个子树做几何缩放会连带缩放
   画布，代价高且明显发糊。

## 5. 地球：高清自然色地表

### 夜间灯光已不再是主体

`uNightIntensity` 由 **1.55 → 0.5**，并新增 `uNightSurface = 0.34`：
自然地表色**延续到夜侧**（压暗并偏冷），城市灯光退为**淡淡的暖色痕迹**。
因此大陆与海洋绕地球一圈都可辨认，而不是在晨昏线处掉进黑里。

### 分辨率：如实说明，未使用分级瓦片

| 项 | 值 |
|---|---|
| 昼面输出 | **4096×2048**（1.07 MB） |
| 上游许可 | 公有领域（NASA / Goddard） |
| 上游可用尺寸 | **3840×1920** |
| 夜间灯光 | DMSP 1994–1995，公有领域，**约三十年前** |
| 云层 | three.js 示例素材（MIT） |

**为什么不做到 8K**：上游经 Wikimedia 缩略服务实际只能取到 **3840×1920**
（Commons 对缩略图的原始宽度上限），而当前 4096×2048 已经**超过**源分辨率。
继续放大只会插值出**虚假细节**，不是真的更清晰。

**为什么不用分级瓦片 / 地图服务**：
- 不能抓取未授权的地图瓦片；
- 不能依赖付费 API 才能启动站点；
- 本项目坚持「不把静态贴图说成实时卫星影像」。

所以选择了**合法且可核查来源的最高可用分辨率**，并把限制写进 `textures.json`
与页面致谢区。若要真正的「地图软件式」放大，需要接入带明确许可的瓦片服务，
那是另一项工作，不在本次范围内。

## 6. 地球交互：两个真实缺陷已修复

### 缺陷 A：键盘层拦截了所有鼠标事件

`.eglobe__keys` 是覆盖整个球体的 `inset: 0` 层，**没有 `pointer-events` 规则**。
它因此是不透明的命中目标：每一次 pointerdown / 拖动 / 滚轮都落在它上面，
**永远到不了 canvas**——拖拽与缩放**在任何浏览器里都不工作**。

修复不只是给覆盖层加 `pointer-events: none`：监听器原本绑在 **canvas** 上，而
canvas 会被 WebGL 重试逻辑**替换元素**。所以监听器全部移到**宿主元素**（`.eglobe`），
它在组件整个生命周期内稳定；命中测试与拖拽缩放也改用宿主的 `getBoundingClientRect()`，
避免读取被替换掉的 canvas。

### 缺陷 B：缩放/旋转按钮已移除

按要求删除了旋转左右、放大、缩小按钮簇，只保留：
- 一行低调操作提示（拖动旋转 / 滚轮缩放 / 点击地区查看详情）
- **重置视角**按钮（唯一难以自行发现的操作）

提示条整体 `pointer-events: none`，只有按钮自身可点，因此它不会吞掉从它上面开始的拖拽。

### 实测（合成真实指针与滚轮事件）

```
element under cursor at centre : .eglobe   (inside the globe host: true)
wheel events default-prevented : 3/3
drag changed rendered pixels   : true
country resolved by raycasting : (0.36, -0.08) id=036
panel opened by a DRAG         : false
panel opened by a CLICK        : true  -> AUSTRALIA / 澳大利亚
canvas count in DOM            : 1
```

8/8 通过。面板内容同时印证了诚实性：澳大利亚显示「尚未记录 … 我还没有去过这里」。

> 说明：测试最初断言「点击会打开地区面板」，结果失败。独立计算后发现当时
> 地球正面朝向 18°N, 107.5°W（墨西哥外海），**7 个采样点全在海上，点击海面
> 正确地不选择任何国家**——是测试错了，不是产品错了。现改为让组件自身的
> `pickAt` 报告哪里有国家，再精确点击那一点。
