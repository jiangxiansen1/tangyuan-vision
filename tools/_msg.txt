feat(earth): replace the fixed-texture globe with a real multi-level map

The Earth page now loads MORE data as you zoom in, which is the only thing that fixes
"no detail when zoomed". The old renderer drew one 4096x2048 texture on a sphere and
zooming only magnified those pixels; its upstream source serves 3840x1920, so the
texture already exceeded it and a sharper copy could not be obtained at all.

NEW RENDERER, AND WHAT EACH ZOOM RANGE ACTUALLY SHOWS
  z0-z4  NASA BlueMarble, the cloud-free reference mosaic - gapless
  z4-z9  NASA GIBS MODIS Terra true colour, z9 is the measured ceiling (z10 is HTTP 400)
  z10+   OpenStreetMap vector data: real roads, buildings and place names

And the UI states which of those you are looking at, because "the satellite imagery ends
here" is a fact the page should not hide.

The old WebGL globe is NOT deleted. It needs no network at all, so it is the fallback when
the map library or the imagery is unreachable - region identification and voting survive
an offline visit, and those are the page's business functions.

THE 174-ROW REGION LIST IS GONE, AND WHAT REPLACED IT
It was doing two jobs that both had to survive: keyboard reachability of every region, and
finding one by name. Both now live in a collapsed search panel - same complete dataset,
reachable on demand, occupying no space until asked for.

FOUR REAL DEFECTS FOUND BY MEASURING
1. MapLibre's worker never started under Vite's dependency pre-bundling: "Worker failed to
   load." The style loaded, 35 raster tiles were fetched and the globe appeared, so it read
   as "slow" rather than broken - but the worker is what parses VECTOR tiles, so `load`
   never fired and the map was never interactive. Fixed with optimizeDeps.exclude, because
   the worker URL is derived from the module's own filename.
2. The PRODUCTION build shipped no worker file at all. Rollup bundled the library into
   assets/vendor-maplibre-*.js, whose worker resolves to assets/maplibre-gl-worker.mjs - a
   file the build never emitted. Measured on the built site: roads 0, water 0,
   place-city 0 vs dev: roads 6383, water 103, place-city 8. A Vite plugin now copies it.
3. TWO elements were conflated. `hostRef` was on the inner MapLibre container while every
   state attribute was written to and read from the outer shell. The symptom was a
   contradiction: `data-status` reached 'ready' while `data-map-ready`, written earlier in
   the same handler, never appeared. Two refs now, each on the element that owns it.
4. The `if (disposed) return` guard in the load handler was wrong. StrictMode mounts,
   cleans up and mounts again, so two Map instances are created and `load` fires on the
   DISPOSED one, whose closure has disposed === true. It returned early, silently, with no
   exception anywhere. It now compares the live ref, which is also correct in production.

THE BLACK STRIPES, AND WHY THE FIRST THREE EXPLANATIONS WERE WRONG
The globe showed dark wedges. Ruled out by measurement, in order: tile URL construction
(35 tiles, all z3, all HTTP 200), wrapped world copies (disabling them changed nothing),
and reprojection artefacts. Fetching an UNTOUCHED tile straight from the server settled
it - the stripes are in NASA's JPEG. They are orbital swath seams, and further south they
are the hard edge of the satellite's coverage, past which nothing was ever observed.
Stacking five dates did not fix it because a swath gap is OPAQUE BLACK, not transparent:
translucent layers converge toward black instead of diluting it, measured across a
1.0 -> 0.62 -> 0.5 -> 0.22 opacity ladder over an opaque gapless base. The global view
therefore uses the mosaic built to be seamless, and daily imagery takes over at z4 where a
continent fills the view and the seams have narrowed.

tools/ gains a CDP driver, because four earlier verification attempts failed on the browser
mechanism rather than on the map, each silently: virtual time never settles for a page with
continuous network activity, --dump-dom fires at the load event which is far too early, and
blocking the load event freezes the main thread the iframe shares.

maplibre-gl is the only new dependency: ~292 KB gzip, its own lazily-loaded chunk, and no
API key or account is required for anything above. VITE_MAPTILER_KEY is optional and only
switches the imagery source to MapTiler when the operator supplies one.
